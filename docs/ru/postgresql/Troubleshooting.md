Устранение неполадок
====================

[English version](../../en/postgresql/Troubleshooting.md)

## Diff пустой, хотя приложение изменило данные

Проверьте по порядку:

1. **Имя подключения.** `name` в `<init>` и тег внутри `<dataStorageDiff>` должны совпадать с ключом
   в `integration.testing.postgresql.connections`.
2. **Одна и та же база.** Фреймворк открывает своё JDBC-подключение. Если приложение пишет в другую
   базу или схему, diff ничего не увидит.
3. **`defaultSchema`.** Для неквалифицированных имён таблиц модуль ищет их в `defaultSchema`.
4. **Триггеры.** Изменения, сделанные при `session_replication_role = 'replica'` или при отключённых
   триггерах, в журнал не попадают.
5. **Начальное состояние.** Diff считается относительно предыдущего кейса или части, а не
   относительно «пустой базы».

Если ошибок нет, но diff всё равно пустой, включите debug-логи фреймворка и проверьте, что таблица
попала в инициализацию.

## `PostgreSQL connection '...' is not configured`

В конфигурации нет подключения с таким именем. Проверьте ключ в
`integration.testing.postgresql.connections` и `name` в XML. Помните, что имя подключения — это не
обязательно имя бина `DataSource`.

## `TestDataStorage '...' not found`

`SqlStorageSetup`/`SqlStorageInit` ссылается на неизвестное хранилище. Проверьте, что:
* подключение объявлено в `connections`;
* `@EnableTestPostgreSQL` стоит на тестовом классе;
* имя в XML совпадает с ключом подключения.

## `Table '...' is not registered in the storage`

Таблица не была найдена в метаданных. Обычно причина одна из двух:

* таблица указана с неверной схемой (`public.users` вместо `users` или наоборот);
* `defaultSchema` не совпадает со схемой, где реально лежит таблица.

Проверьте `defaultSchema` и имена таблиц в `tablesToClear`/`tablesToLoad`.

## Ошибки прав доступа

Если при старте теста падает создание журнала, функций или триггеров, учётной записи не хватает
прав. Нужны права на:

* создание таблицы, последовательности, функций и триггеров в схеме;
* создание и удаление триггеров на тестируемых таблицах;
* `SET session_replication_role`;
* `ALTER SEQUENCE ... RESTART`;
* чтение и запись в служебный журнал.

В тестовой среде проще использовать владельца схемы или отдельную роль с явно выданными правами.
Если `SET session_replication_role` запрещён, модуль не сможет загружать фикстуры и выполнять
служебные SQL-переходы.

## `bytea` отображается как текст

Проверьте настройку PostgreSQL:

```sql
SHOW bytea_output;
```

Модуль рассчитан на `hex`. При `escape` бинарные значения могут выглядеть как текст, а не как
`byte[]` в Base64.

## Ошибка конвертации колонки

Сообщение вида:

```text
Failed to convert PostgreSQL column public.events.payload of type jsonb
```

означает, что значение не удалось преобразовать в соответствии с настройкой `columns`. Проверьте:

* `type`/`bean-ref` для этой колонки;
* `target-class`, если используется `json`;
* что JSON-структура действительно соответствует ожидаемому DTO.

Если для колонки настроен свой конвертер, встроенный fallback не используется. Исправлять нужно
саму настройку или конвертер.

## Таблица без первичного ключа

Если у таблицы нет PK, ключ строки в diff — хеш всего содержимого. Обновление такой строки
показывается как удаление старой и добавление новой. Это ожидаемое поведение.

Если нужны стабильные ключи и удобный откат, добавьте первичный ключ. Для составного ключа
используйте колонки с простыми значениями.

## Не работает `hstore`

Убедитесь, что расширение установлено в базе:

```sql
CREATE EXTENSION IF NOT EXISTS hstore;
```

Без расширения PostgreSQL не сможет создать `hstore`-колонку, и тест упадёт ещё на этапе схемы.

## Нет атрибута `change` в diff

Проверьте настройку формы diff:

```yaml
integration:
  testing:
    storage:
      storages:
        dataSource:
          keyType: [ STRING, OBJECT ]
          valueType: [ OBJECT, OBJECT ]
          changeType: [ false, true ]
```

Без `changeType` записи могут выводиться без `change="added|changed|deleted"`.

## Данные не загрузились из DBUnit

`SqlStorageSetup` только регистрирует датасет. Чтобы данные попали в таблицу, нужен
`SqlStorageInit`:

```xml
<init type="SqlStorageInit" name="dataSource">
    <tablesToLoad>users</tablesToLoad>
</init>
```

или `loadAllTables="true"`. Также проверьте, что таблица есть в датасете и имя совпадает.

## DDL не подхватился

Схему и изменения структуры лучше выполнять в `SqlStorageSetup`. После изменения SQL модуль
сбрасывает кэш метаданных. DDL, выполненный в произвольном месте теста, может не обновить
метаданные таблиц.

## Ошибки Testcontainers / Docker

Если используется embedded-режим, проверьте, что Docker запущен и доступен. Для внешней базы
отключите embedded-режим и задайте `host`, `port`, `database`, `user`, `password` явно.
