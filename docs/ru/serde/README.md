Сериализация и десериализация (Serde)
=====================================

[English version](../../en/serde/README.md)

Serde отвечает за то, в каком виде данные уходят и приходят: JSON, XML, строка, сырые байты или
бинарный конверт. Настройки форматов пишутся в `application-test.yml` — для сообщения или значения
целиком либо для его отдельных частей (в Kafka — `key`/`value`, в Redis — `value`/`hash-key`/
`hash-value`). Эта страница — общая часть; специфика платформ — в разделах
[Kafka](../kafka/Serde.md) и [Redis](../redis/Configuration.md).

Откуда берётся формат
---------------------

Источник формата задаётся одним из трёх способов:

* `type` **без точки** — имя встроенного формата: `json`, `xml`, `yaml`, `string`, `bytes`;
* `bean-ref` — имя готового Spring-бина (например, вашего сериализатора);
* `type` **с точкой** — полное имя класса: Spring создаст бин сам.

Если в проекте уже есть нативные сериализаторы (Kafka `Serializer`/`Deserializer`, Spring Data
`RedisSerializer`, Redisson `Codec`), их тоже можно указать через `bean-ref` или по классу — фреймворк
подключит их сам.

Если нужен свой формат — см. [Расширяемость](Extensibility.md).

Выбор источника
---------------

| Поле       | Что делает                                                                      |
|------------|---------------------------------------------------------------------------------|
| `type`     | имя провайдера (`json`, `xml`, `string`, `yaml`, `bytes`) или полное имя класса |
| `bean-ref` | имя готового Spring-бина: источник берётся как есть, кроме `binary-envelope`    |

* `type` **без точки** — имя зарегистрированного провайдера. Набор доступных имён зависит от уровня
  настройки и платформы.
* `type` **с точкой** — fully qualified class name: Spring создаёт бин, `target-class` и
  `object-mapper-ref` к нему не применяются.
* `bean-ref` и `type` взаимоисключающие на одном уровне: это два способа задать источник.

Общие поля
----------

| Поле                | Применяется                | Описание                                                                    |
|---------------------|----------------------------|-----------------------------------------------------------------------------|
| `target-class`      | только с именем провайдера | класс, с которым работает сериализация и в который десериализуется значение |
| `object-mapper-ref` | только с именем провайдера | имя бина `ObjectMapper` для Jackson-форматов (`json`, `xml`, `yaml`)        |
| `binary-envelope`   | рядом с источником         | шаблон бинарного конверта — см. [Бинарные упаковки](Binary-Envelopes.md)    |

`target-class` и `object-mapper-ref` работают только вместе с именем провайдера: `bean-ref`
возвращает готовый бин как есть, а класс по FQCN создаётся Spring-ом без дополнительной настройки.
`binary-envelope` — исключение: конверт накладывается и на `bean-ref`, и на FQCN, и на провайдера —
см. [Бинарные упаковки](Binary-Envelopes.md).

`binary-envelope` без источника на том же уровне отклоняется: конверту нечего оборачивать. В Redis
компонент схемы наследует источник от родительской схемы слиянием параметров, поэтому у компонента
допускается задать только `binary-envelope` — см.
[Конфигурацию Redis](../redis/Configuration.md#наследование-компонентов-схемы).

Ядровые провайдеры
------------------

| `type`   | Формат       | `target-class`/`object-mapper-ref` |
|----------|--------------|------------------------------------|
| `string` | строки UTF-8 | нет                                |
| `json`   | Jackson JSON | да                                 |
| `xml`    | Jackson XML  | да                                 |
| `yaml`   | Jackson YAML | да                                 |
| `bytes`  | сырые байты  | нет                                |

Набор провайдеров на конкретном уровне (запись целиком, часть записи, компонент схемы) и
платформенные форматы (`spring-json`, `spring-xml`) описаны на страницах платформ:
[Kafka](../kafka/Serde.md), [Redis](../redis/Configuration.md).

Наследование настроек
---------------------

Настройки serde сливаются по уровням (глобальный → подключение → топик/схема):

* простые поля перекрываются значением дочернего уровня;
* вложенные настройки сливаются рекурсивно;
* если дочерний уровень задал свой источник (`type` или `bean-ref`) либо разбил настройку на части
  (`key`/`value`/`headers` или `value`/`hash-key`/`hash-value`), настройка родителя не подмешивается:
  нельзя одновременно унаследовать «источник целиком» и переопределить его часть;
* незаданные части могут добираться из родительской настройки платформы: в Redis частично заданная
  схема (например, только `value`) получает недостающие кодеки из родительской схемы — см.
  [Конфигурацию Redis](../redis/Configuration.md#наследование-компонентов-схемы).

Если на одном уровне оказались несовместимые поля (например, `bean-ref` вместе с `type`), старт
контекста падает с понятной ошибкой — см. «Диагностика».

Диагностика
-----------

| Ошибка                                                                                                                  | Причина и решение                                                                                                                                                    |
|-------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `Unknown serde provider [x] for config [C]. Known providers: [...]`                                                     | Провайдера с таким именем нет для этого уровня. Проверьте список доступных имён в тексте ошибки и на странице платформы.                                             |
| `No converter for [X -> Y] under config [C]`                                                                            | Для класса конфига не нашлось ни одной фабрики конвертеров (нет источника, нет фабрики под этот конфиг). Обычно означает, что конфиг использован не на своём уровне. |
| `No adapter from [X] to [Y] under config [C]`                                                                           | Источник такого типа не поддерживается. Используйте поддерживаемый формат; для своего формата — см. [Расширяемость](Extensibility.md).                               |
| `Both 'beanRef' and 'type' are set on the same serde config`                                                            | Взаимоисключающие способы задать источник. Оставьте один.                                                                                                            |
| `No bean named [x] ...` / `Bean named [x] is not of type [...]`                                                         | Бин из `bean-ref`/`object-mapper-ref` не найден или имеет другой тип. Проверьте имя и определите бин нужного типа.                                                   |
| `Field 'targetClass'/'objectMapperRef' has no effect when 'beanRef' is set` (или `... is a fully qualified class name`) | Эти поля применяются только с именем провайдера. Уберите их или перейдите на `type: <провайдер>`.                                                                    |
| `Field 'binaryEnvelope' has no effect without a source ...`                                                             | Конверт оборачивает источник, а источника на этом уровне нет. Положите `binary-envelope` рядом с источником.                                                         |

Если нужен свой формат, фабрика или адаптер — см. [Расширяемость](Extensibility.md).
