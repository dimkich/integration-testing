Конфигурация модуля Kafka: Справочник параметров
================================================

[English version](../../en/kafka/Configuration.md)

Все настройки Kafka живут в `application-test.yml` под префиксом `integration.testing.kafka`.
Настройки трёхуровневые и наследуются сверху вниз: глобальные → подключение → топик.

Уровни настройки
----------------

```text
integration.testing.kafka.*                          (глобальные значения)
        │
        ▼
integration.testing.kafka.connections.<имя>.*        (настройки подключения)
        │
        ▼
...connections.<имя>.topics.<regex>.*                (настройки конкретного топика)
```

Каждый ключ в `connections` — это логическое подключение. Для него фреймворк создаёт собственные
producer, sniffer-consumer и admin-клиент. Приложение при этом продолжает пользоваться своими
клиентами (например, настроенными через `spring.kafka.bootstrap-servers`).

### Правила наследования

* скалярные значения (`ignore`, `ignore-inbound`) перекрываются значением дочернего уровня;
* наборы (`excluded-fields`) объединяются;
* `serializer` и `deserializer` сливаются рекурсивно, но группа `type`/`bean-ref`/`key`/`value`/`headers`
  эксклюзивна: если дочерний уровень задал хотя бы один элемент группы, остальные элементы с
  родительского уровня не наследуются. Так исключается смешивание «настройки записи целиком» и
  «настройки по частям» с разных уровней;
* карты `connections` и `topics` не наследуются — их ключи задаются на своём уровне.

Исчерпывающий справочник параметров
-----------------------------------

### Параметры глобального уровня (`integration.testing.kafka.*`)

| Параметр                                | Тип          | По умолчанию | Описание                                                       |
|-----------------------------------------|--------------|--------------|----------------------------------------------------------------|
| `serializer`                            | объект Serde | не задан     | сериализация отправляемых сообщений по умолчанию               |
| `deserializer`                          | объект Serde | не задан     | десериализация пойманных сообщений по умолчанию                |
| `ignore`                                | boolean      | `false`      | исключить топики из захвата сниффером                          |
| `ignore-inbound`                        | boolean      | `true`       | не показывать в проверках сообщения, отправленные самим тестом |
| `excluded-fields`                       | список строк | не задан     | поля, исключаемые из сравнения сообщений                       |
| `lag-polling-interval-ms`               | long         | `5`          | пауза между проверками лага, мс                                |
| `lag-polling-timeout-ms`                | long         | `10000`      | сколько всего ждать исчезновения лага, мс                      |
| `readiness-polling-interval-ms`         | long         | `100`        | пауза между проверками готовности ожидаемых consumer-групп, мс |
| `startup-stabilization-timeout-seconds` | long         | `30`         | ожидание стабилизации consumer-групп при старте, сек           |
| `connections`                           | карта        | не задана    | подключения к брокерам                                         |

### Параметры уровня подключения (`integration.testing.kafka.connections.<ИМЯ>.*`)

| Параметр                                                                    | Тип          | По умолчанию | Описание                                                                             |
|-----------------------------------------------------------------------------|--------------|--------------|--------------------------------------------------------------------------------------|
| `bootstrap-servers`                                                         | строка       | обязателен   | адрес брокера: `host:port` или список через запятую                                  |
| `properties`                                                                | карта        | `{}`         | дополнительные свойства Kafka-клиента (`acks`, `security.protocol`, `sasl.*` и т.д.) |
| `topics`                                                                    | карта        | не задана    | настройки топиков; ключ — регулярное выражение                                       |
| `expected-groups`                                                           | список строк | не задан     | consumer-группы SUT, готовности которых ждём перед тестом и в цикле ожидания         |
| `serializer`, `deserializer`, `ignore`, `ignore-inbound`, `excluded-fields` |              |              | наследуются от глобального уровня                                                    |

Если `bootstrap-servers` не задан, при старте контекста будет ошибка — подключение без адреса брокера
не создаётся.

### Параметры уровня топика (`integration.testing.kafka.connections.<ИМЯ>.topics.<REGEX>.*`)

| Параметр          | Тип          | По умолчанию | Описание                                           |
|-------------------|--------------|--------------|----------------------------------------------------|
| `serializer`      | объект Serde | наследуется  | как сериализовать сообщения из `<inboundMessage>`  |
| `deserializer`    | объект Serde | наследуется  | как десериализовать пойманные сообщения            |
| `ignore`          | boolean      | наследуется  | исключить топик из захвата сниффером               |
| `ignore-inbound`  | boolean      | наследуется  | не показывать сообщения, отправленные самим тестом |
| `excluded-fields` | список строк | наследуется  | поля, исключаемые из сравнения                     |

### Объект Serde (`serializer` и `deserializer`)

| Поле                        | Описание                                                                                                                               |
|-----------------------------|----------------------------------------------------------------------------------------------------------------------------------------|
| `type`                      | имя формата (`json`, `xml`, `string`, `bytes`, `yaml`, `spring-json`, `spring-xml`) или полное имя класса (`com.example.MySerializer`) |
| `bean-ref`                  | имя готового Spring-бина. Бин используется как есть, остальные поля игнорируются                                                       |
| `target-class`              | класс, в который десериализуется значение. Работает только вместе с именем формата                                                     |
| `object-mapper-ref`         | имя бина `ObjectMapper` для Jackson-форматов. Работает только вместе с именем формата                                                  |
| `key` / `value` / `headers` | отдельные настройки Serde для ключа, значения и заголовков                                                                             |
| `add-type-info-headers`     | `spring-json`/`spring-xml`: добавлять тип в заголовки при сериализации                                                                 |
| `use-type-info-headers`     | `spring-json`/`spring-xml`: читать тип из заголовков при десериализации                                                                |
| `trusted-packages`          | `spring-json`/`spring-xml`: пакеты, которым разрешён разбор типов (`*` — все)                                                          |

Провайдеры `spring-json` и `spring-xml` доступны только в `serializer`/`deserializer` целиком — внутри
`key`/`value`/`headers` используйте `json`/`xml` (тот же формат, но без информации о типе).

### Допустимые и запрещённые комбинации

| Комбинация                                                            | Результат                                                                    |
|-----------------------------------------------------------------------|------------------------------------------------------------------------------|
| `type: json`                                                          | можно                                                                        |
| `type: json` + `target-class`                                         | можно                                                                        |
| `type: json` + `key`/`headers`                                        | можно: провайдер собирает запись, части переопределяют значения по умолчанию |
| `type: <полное имя класса>`                                           | можно                                                                        |
| `bean-ref: myBean`                                                    | можно                                                                        |
| `type: json` + `value`                                                | нельзя: провайдер записи уже отвечает за значение                            |
| `bean-ref` + `key`/`value`/`headers`                                  | нельзя: готовый бин используется целиком                                     |
| `bean-ref` + `type`                                                   | нельзя: это взаимоисключающие способы задать источник                        |
| `type: <полное имя класса>` + `key`/`headers`                         | нельзя: класс обрабатывает запись целиком                                    |
| `bean-ref` или полное имя класса + `target-class`/`object-mapper-ref` | нельзя: эти поля к ним не применяются                                        |

Неверная комбинация приводит к ошибке при старте контекста, например:

```text
Invalid serializer config at connection[kafka1].topics[order-in]: Conflicting serde config: ...
```

В сообщении написано, что именно конфликтует и как исправить конфигурацию.

Сопоставление топиков по регулярному выражению
----------------------------------------------

Ключи `topics` — это регулярные выражения, а не точные имена. Проверяется **полное** совпадение имени
топика с выражением. Правила:

* первое совпавшее выражение выигрывает — важен порядок в файле;
* результат сопоставления кэшируется при первом обращении к топику;
* избегайте перекрывающихся выражений: иначе победитель зависит от порядка в YAML;
* если не совпало ни одно выражение, применяются настройки подключения.

```yaml
topics:
  "order-created": # точное имя
    serializer:
      type: json
  "order-.*": # всё, что начинается с order-
    deserializer:
      type: json
  ".*-events": # всё, что заканчивается на -events
    deserializer:
      type: string
```

Флаги `ignore` и `ignore-inbound`
---------------------------------

`ignore: true` — топик не захватывается сниффером: сообщения приложения из него не попадут в
`<outboundMessage>`. Отправлять сообщения в такой топик из теста при этом можно — `<inboundMessage>`
продолжит работать.

`ignore-inbound: true` (по умолчанию) — из пойманных сообщений исключаются те, которые отправил сам
тест. Это защищает от «эха»: если приложение пересылает или логирует входные сообщения, они не
появятся в проверках. Укажите `false` для подключения-«монитора», если нужно видеть полный поток,
включая отправленное тестом:

```yaml
connections:
  kafka1:
    bootstrapServers: ${embedded.kafka.brokerList}
    ignoreInbound: false
    excludedFields:
      - partition
      - offset
      - timestamp
```

Исключение полей (`excluded-fields`)
------------------------------------

Список путей, которые не участвуют в сравнении сообщений. Поддерживаются вложенные пути с точкой:

```yaml
excluded-fields:
  - partition
  - offset
  - timestamp
  - headers.id
  - headers.kafka_offset
```

Чаще всего исключают технические поля: `partition`, `offset`, `timestamp` и служебные заголовки Kafka —
они всегда разные и не относятся к логике теста.

Ожидание готовности SUT (`expected-groups`)
-------------------------------------------

Если контейнеры приложения стартуют асинхронно (например, после старта Spring-контекста), на момент
первого теста consumer-групп SUT на брокере может ещё не быть. Перечислите их в `expected-groups`,
чтобы фреймворк дождался появления групп, их стабилизации и назначения партиций:

```yaml
connections:
  kafka1:
    bootstrapServers: ${embedded.kafka.brokerList}
    expected-groups:
      - fix-adapter.input.id
      - fix-adapter.output.id
```

Как это работает:

* перед каждым тестом (`start()`) фреймворк ждёт до `startup-stabilization-timeout-seconds`, пока
  каждая группа не станет готовой — живые участники с назначенными партициями («running + assigned»).
  Если не дождался — тест падает с сообщением `Kafka startup stabilization timeout ...`;
* в каждом цикле ожидания после отправки (`waitCompletion()`) проверка повторяется: пока ожидаемые
  группы не готовы, «лаг исчез» не считается завершением. Проверки готовности идут не чаще, чем раз
  в `readiness-polling-interval-ms`;
* пустой или отсутствующий список — прежнее поведение: ждём только известные группы, пустой листинг
  не блокирует;
* несколько подключений к одному кластеру объединяют свои списки.

Как определяется готовность, зависит от режима:

* `inflight = true` (по умолчанию) — по инструментированным клиентам в памяти: группа считается
  готовой, когда все её консьюмеры получили партиции (по колбэкам ребаланса), а при ручном `assign` —
  сразу после назначения. Обращений к брокеру нет; группы внешних процессов не видны — для них нужен
  `inflight = false`;
* `inflight = false` — через Admin API: группа должна быть `STABLE` и иметь живых участников с
  назначенными партициями.

Ограничение режима `inflight = false`: группы, которые назначают партиции вручную
(`@KafkaListener(topicPartitions = ...)`), на брокере видны как `EMPTY` (у них нет участников
группы), поэтому в `expected-groups` их указывать нельзя — ожидание по ним завершится ошибкой. В
`inflight = true` ручной `assign` отслеживается, и такие группы можно указывать.

Реальный брокер в тестах
------------------------

`@EnableTestKafka` подключает `real-kafka.properties`: и приложение, и фреймворк работают с настоящим
брокером, который Testcontainers поднимает в Docker. Адрес брокера доступен как
`${embedded.kafka.brokerList}`. Если Docker не запущен, тесты Kafka работать не будут.

Полный практический пример конфигурации
---------------------------------------

```yaml
integration:
  testing:
    kafka:
      connections:
        kafka1:
          bootstrapServers: "${embedded.kafka.brokerList}"
          expected-groups:
            - order-processor
          excluded-fields:
            - partition
            - offset
            - timestamp
            - headers.id
            - headers.kafka_offset
          topics:
            "order-in":
              serializer:
                type: json
            "order-out":
              deserializer:
                type: json
                target-class: com.example.kafka.OrderEvent
            "notification-.*":
              serializer:
                type: spring-json
                add-type-info-headers: true
              deserializer:
                type: spring-json
                use-type-info-headers: true
                trusted-packages: "*"
        monitor:
          bootstrapServers: "${embedded.kafka.brokerList}"
          ignoreInbound: false
          excluded-fields:
            - partition
            - offset
            - timestamp
```
