# Система Wait-Completion

[English version](../en/wait-completion.md)

Wait-Completion ждёт завершения фоновых задач приложения без `Thread.sleep()` и без правок кода
приложения. Вы описываете аннотацией, где начинается и заканчивается работа, а фреймворк
останавливает тест, пока эта работа не завершится.

## Включение

Подсистема выключена по умолчанию. Включите её свойством:

```yaml
integration:
  testing:
    wait:
      completion:
        enabled: true
```

Аннотации `@EnableTestRedis` и `@EnableTestKafka` включают её сами через свои `properties`.
Аннотации ожидания ставятся на тестовый класс, который уже включает фреймворк
(`@IntegrationTesting` или аннотация модуля).

## Общие атрибуты

* `pointcut` — какие классы и методы инструментировать (переменные `t` и `m`);
* `when` — при каких вызовах учитывать активность (переменные `o` и `a`); по умолчанию `true`.

```text
pointcut = "t.inherits('com.app.BaseProcessor') && m.name('process')"
when     = "o.isSameClass(com.app.CriticalProcessor.class)"
```

Полный синтаксис и функции `t`, `m`, `o`, `a` — в разделе [DSL выражений](Expression-DSL.md).
`pointcut` должен быть узким: инструментация каждого метода приложения замедляет тесты.

## Выбор стратегии

| Ситуация в коде                    | Стратегия              | Когда задача считается завершённой |
|------------------------------------|------------------------|------------------------------------|
| Есть объект-дескриптор задачи      | `@FutureLikeAwait`     | Заблокировались на методе объекта  |
| Задача — это выполнение метода     | `@MethodCountingAwait` | Выход из метода                    |
| Старт и конец — разные методы      | `@MethodPairAwait`     | Баланс вызовов start/end           |
| У сервиса есть очередь или счётчик | `@QueueLikeAwait`      | Очередь опустела                   |

### `@FutureLikeAwait`

Для `CompletableFuture`, `Thread`, Apache MINA `IoFuture` или своего класса-задачи, у которого
есть блокирующий метод (`join()`, `get()`, `await()`).

```java
@FutureLikeAwait(
        pointcut = "t.name('com.app.Task') && m.isConstructor()",
        await = "o.call('await')")
```

* `await` — DSL-вызов блокирующего метода;
* `awaitConsumer` — класс `Consumer<Object>` для сложного ожидания; нужен public no-args
  конструктор.

### `@MethodCountingAwait`

Задача — это выполнение метода: вход в целевой метод начинает задачу, выход (в том числе по
исключению) завершает. Тест ждёт, пока все такие задачи не закончатся.

```java
@MethodCountingAwait(
        pointcut = "t.name('com.app.OrderHandler') && m.name('onMessage')")
```

Подходит для обработчиков сообщений, слушателей и воркеров. Обязательно указывайте конкретный
метод в `pointcut`, иначе задачами станет каждый вызов.

### `@MethodPairAwait`

Связывает два разных метода в одну задачу: например, запрос уходит из одного компонента, а ответ
обрабатывается в другом.

```java
@MethodPairAwait(
        startPointcut = "t.name('com.app.Gateway') && m.name('send')",
        endPointcut = "t.name('com.app.ResponseHandler') && m.name('onAck')")
```

* `startPointcut` / `startWhen` — начало задачи;
* `endPointcut` / `endWhen` — завершение задачи.

Условия `startWhen` и `endWhen` должны быть согласованы: если start учтён, а end — нет, счётчик
останется положительным и ожидание не завершится.

### `@QueueLikeAwait`

Для сервиса, который сам знает размер своей очереди или пула.

```java
@QueueLikeAwait(
        pointcut = "t.name('com.app.Worker') && m.isConstructor()",
        size = "o.call('getQueueSize').asInt()")
```

* `size` — DSL-выражение, возвращающее `Integer`;
* `sizeFunction` — класс `Function<Object, Integer>` для сложного подсчёта; нужен public no-args
  конструктор.

Если в `pointcut` не указан метод, инструментируются конструкторы подходящего типа.

## Как это работает

Перед каждым действием теста (и перед инициализацией) открывается новое окно активности. После
действия координатор запускает все стратегии параллельно; каждая ждёт, пока её подсистема не
опустеет. Если хотя бы одна стратегия сообщила активность, цикл повторяется: событие в одной
подсистеме могло вызвать каскад в другой. Когда все стратегии вернули `false`, тест переходит к
проверкам.

Ошибка ожидания (таймаут Kafka, падение репликатора Redis) сразу пробрасывается в тестовый поток,
не дожидаясь общего таймаута теста.

## Ограничения

* Задача должна проходить через точку перехвата. Если библиотека создаёт задачи внутри себя,
  добавьте её класс или пакет в `pointcut`.
* Для `@MethodPairAwait` следите за согласованностью `startWhen` и `endWhen`.
* Не ставьте `pointcut` на весь classpath: инструментируются все подходящие вызовы.
* Ожидание не заменяет проверку ответа: diff и `<response>` всё равно сравниваются после
  завершения фоновой работы.
