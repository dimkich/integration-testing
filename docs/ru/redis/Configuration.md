Конфигурация модуля Redis: Справочник параметров
=================================================

[English version](../../en/redis/Configuration.md)

Все параметры тестирования Redis описываются в стандартных конфигурационных файлах Spring Boot (таких
как `application.yml` или `application-test.yml`) под префиксом `integration.testing.redis`.

Настройки позволяют декларативно связывать файлы конфигурации со Spring-бинами соединений в вашем
проекте, автоматически наследовать общие параметры и бесконфликтно разрешать правила сериализации.

Связь конфигурации со Spring-бинами подключений (Connections)
-------------------------------------------------------------

Ключевым разделом является блок `connections`. Имена подразделов в этой секции должны в точности
совпадать с именами бинов `RedisConnectionFactory`, которые объявлены в Java-коде вашего приложения.

Если в вашем проекте объявлены две фабрики соединений (например, одна для Jedis, другая для Redisson):

```java

@Configuration
public class MyRedisAppConfig {

    @Bean
    public RedisConnectionFactory redissonConnectionFactory() {
        return new RedissonConnectionFactory(...);
    }

    @Bean
    public RedisConnectionFactory jedisConnectionFactory() {
        return new JedisConnectionFactory(...);
    }
}
```

То в файле `application-test.yml` вы описываете подключение, используя эти же имена бинов в качестве
ключей в блоке `connections`:

```yaml
integration:
  testing:
    redis:
      connections:
        # Имя ключа совпадает с именем бина @Bean для Redisson
        redissonConnectionFactory:
          host: "localhost"
          port: 6379

        # Имя ключа совпадает с именем бина @Bean для Jedis
        jedisConnectionFactory:
          host: "localhost"
          port: 6380
```

Если ваше приложение использует стандартную автоконфигурацию Spring Boot и у вас только одна база
данных, то имя бина по умолчанию — `redisConnectionFactory`.

Пошаговая схема наследования и глубокого слияния (Deep Merge)
-------------------------------------------------------------

Параметры не просто копируются, а проходят через трехуровневый процесс глубокого объединения сверху вниз:

```
[ Уровень 1: Глобальные настройки ] (задаются прямо в `integration.testing.redis.*`)
                 │
                 ▼
  [ Уровень 2: Настройки Подключения ] (переопределяют глобальные для конкретного бина)
                 │
                 ▼
  [ Уровень 3: Настройки Схемы Ключа ] (задают правила для конкретной маски/префикса ключа)
```

### Правила слияния параметров

**Простые значения (String, Integer, Boolean, Long):**

* Если у дочернего объекта (например, конкретной схемы) значение поля равно `null`, оно заменяется
  унаследованным значением родителя.
* Если у дочернего объекта поле заполнено, оно сохраняется, а значение родителя игнорируется.

**Списки и множества (`Set<String>` excludedFields):**

* Выполняется операция объединения (Union). Все уникальные элементы из родительских списков добавляются
  к дочернему.
* Пример: Если на глобальном Уровне 1 вы указали исключить `createdAt`, на Уровне подключения 2 вы
  добавили `updatedAt`, а на Уровне схемы конкретного ключа 3 вы добавили `hits` — фреймворк
  автоматически исключит все три поля: `createdAt`, `updatedAt` и `hits`.

**Эксклюзивные группы свойств (аннотация `@PropertyInheritanceExclusive`):**

* Поля, определяющие способ указания сериализаторов — имя Spring-бина (`beanRef`) и полное имя
  Java-класса кодека (`classRef`) — объединены в эксклюзивную группу `"ref"`.
* Правило группы: Если в дочерней конфигурации заполнено хотя бы одно поле из эксклюзивной группы,
  то ни одно из полей этой группы не будет унаследовано от родителя. Это предотвращает возникновение
  конфликта (например, когда дочерний объект хочет использовать локальный `classRef`, но из-за
  наследования получает ещё и родительский `beanRef`).

Исчерпывающий справочник всех параметров
----------------------------------------

### Параметры Глобального уровня (`integration.testing.redis.*`)

Эти настройки применяются ко всем подключениям по умолчанию.

| Параметр               | Тип                       | Описание                                                                     | Значение по умолчанию        |
|------------------------|---------------------------|------------------------------------------------------------------------------|------------------------------|
| `host`                 | String                    | Хост для подключения к Redis (репликатор подключается к нему)                | `${embedded.redis.host}`     |
| `port`                 | Integer                   | Порт для подключения к Redis                                                 | `${embedded.redis.port}`     |
| `user`                 | String                    | Имя пользователя для авторизации в Redis (root приравнивается к null)        | `${embedded.redis.user}`     |
| `password`             | String                    | Пароль для авторизации                                                       | `${embedded.redis.password}` |
| `multipleDatabases`    | Boolean                   | Режим поддержки разделения ключей по индексам баз данных (`SELECT`)          | `false`                      |
| `syncBarrierTimeoutMs` | Long                      | Максимальное время ожидания барьера синхронизации репликации в миллисекундах | `5000`                       |
| `keyCodec`             | Codec                     | Конфигурация глобального кодека для ключей                                   | `StringRedisDataCodec`       |
| `defaultSchema`        | Schema                    | Глобальная схема сериализации по умолчанию                                   | `StringRedisDataSchema`      |
| `excludedFields`       | Set\<String\>             | Глобальный список исключаемых полей для сравнения в DTO/мапах                | Пусто                        |
| `connections`          | Map\<String, Connection\> | Карта подключений Redis, ключи — имена бинов `RedisConnectionFactory`        | Пусто                        |

### Структура объекта Кодека (`keyCodec` или `Codec`)

Используется для конфигурирования правил работы с ключами СУБД.

| Параметр            | Тип           | Описание                                                                     | Эксклюзивность |
|---------------------|---------------|------------------------------------------------------------------------------|----------------|
| `beanRef`           | String        | Имя Spring-бина кодека `RedisDataCodec`                                      | Группа `"ref"` |
| `classRef`          | String        | Полное имя класса кодека `RedisDataCodec` для создания через рефлексию       | Группа `"ref"` |
| `excludedFields`    | Set\<String\> | Список исключаемых полей внутри структуры ключа (если ключ — сложный объект) | —              |
| `valueBinaryFormat` | String        | Шаблон бинарной упаковки ключей                                              | —              |

### Структура объекта Схемы (`defaultSchema`, `Schema`)

Используется для конфигурирования правил работы со значениями (простыми значениями, элементами
коллекций или полями хэшей).

| Параметр                | Тип           | Описание                                                                               | Эксклюзивность |
|-------------------------|---------------|----------------------------------------------------------------------------------------|----------------|
| `beanRef`               | String        | Имя Spring-бина схемы `RedisDataSchema` или класса интеграции (`RedisTemplate`)        | Группа `"ref"` |
| `classRef`              | String        | Полное имя класса схемы `RedisDataSchema` для создания через рефлексию                 | Группа `"ref"` |
| `ignore`                | Boolean       | `true` — полностью игнорировать подходящие под эту схему ключи (скрыть их из проверок) | —              |
| `excludedFields`        | Set\<String\> | Список полей значений этих ключей, которые будут исключены из сравнения                | —              |
| `valueBinaryFormat`     | String        | Шаблон бинарной упаковки простых значений и элементов списков/множеств                 | —              |
| `hashKeyBinaryFormat`   | String        | Шаблон бинарной упаковки ключей хэша (Hash Fields)                                     | —              |
| `hashValueBinaryFormat` | String        | Шаблон бинарной упаковки значений хэша (Hash Values)                                   | —              |

### Параметры уровня Подключения (`connections.<ConnectionFactoryName>.*`)

Описывают настройки для конкретной фабрики `RedisConnectionFactory`. Вы можете переопределить здесь
любые параметры Глобального уровня:

| Параметр            | Тип                                                                      | Описание                                                                                 | Наследование                                               |
|---------------------|--------------------------------------------------------------------------|------------------------------------------------------------------------------------------|------------------------------------------------------------|
| `host`              | String                                                                   | Хост для подключения к Redis (репликатор подключается к нему)                            | Переопределяет глобальный `host`                           |
| `port`              | Integer                                                                  | Порт для подключения к Redis                                                             | Переопределяет глобальный `port`                           |
| `user`              | String                                                                   | Имя пользователя для авторизации в Redis (root приравнивается к null)                    | Переопределяет глобальный `user`                           |
| `password`          | String                                                                   | Пароль для авторизации                                                                   | Переопределяет глобальный `password`                       |
| `multipleDatabases` | Boolean                                                                  | Режим поддержки разделения ключей по индексам баз данных (`SELECT`)                      | Переопределяет глобальный `multipleDatabases`              |
| `keyCodec`          | [`Codec`](#структура-объекта-кодека-keycodec-или-codec)                  | Конфигурация кодека для ключей этого подключения                                         | Полностью замещает глобальный `keyCodec`                   |
| `defaultSchema`     | [`Schema`](#структура-объекта-схемы-defaultschema-schema)                | Схема сериализации по умолчанию для этой фабрики                                         | Полностью замещает глобальный `defaultSchema`              |
| `excludedFields`    | Set\<String\>                                                            | Список исключаемых полей для сравнения в DTO/мапах                                       | Объединяется (Union) с глобальным списком                  |
| `schemas`           | Map\<String, [`Schema`](#структура-объекта-схемы-defaultschema-schema)\> | Карта индивидуальных схем для групп ключей (Уровень 3). Ключами выступают префиксы масок | Не наследуется (определяется только на уровне подключения) |

Разрешение паттернов ключей (Longest-Prefix Match)
---------------------------------------------------

При получении любого ключа из Redis фреймворк должен определить, какую схему использовать. Для этого
`ConnectionSchemaRegistry` выполняет поиск по префиксному дереву (Trie):

1. Ключ переводится в строковое представление с помощью кодека ключей.
2. Фреймворк ищет наиболее длинный совпадающий префикс среди ключей секции `schemas`.
3. Если совпадение найдено, применяется конфигурация этой схемы.
4. Если совпадение не найдено, применяется дефолтная схема подключения (`defaultSchema`).

### Пример работы поиска

Предположим, у нас настроена следующая конфигурация схем:

```yaml
schemas:
  "redisson.TestRedisDto": # Схема А
    bean-ref: testRedisTemplate
  "redisson.TestRedisDto.backup": # Схема Б
    ignore: true
```

| Ключ                               | Наиболее длинный префикс       | Результат                               |
|------------------------------------|--------------------------------|-----------------------------------------|
| `redisson.TestRedisDto:123`        | `redisson.TestRedisDto`        | Применяется Схема А                     |
| `redisson.TestRedisDto.backup:999` | `redisson.TestRedisDto.backup` | Применяется Схема Б (ключ игнорируется) |
| `redisson.otherKey`                | Совпадений нет                 | Применяется `defaultSchema`             |

### Экранирование спецсимволов в YAML

Если ваши ключи содержат точки, квадратные скобки или другие спецсимволы, оборачивайте префиксы
в кавычки и квадратные скобки, чтобы YAML-парсер распознал их корректно:

```yaml
schemas:
  "[redisson.bit]": # Обязательно в кавычках и скобках при наличии точек
    class-ref: io.github.dimkich.integration.testing.redis.schema.ByteArrayRedisDataSchema
```

Игнорирование технического «шума» (`ignore: true`)
---------------------------------------------------

Часто во время теста фоновые процессы приложения пишут в Redis техническую информацию (сервисные
логи, сессии фоновых задач, блокировки замков Lock). Эти изменения засоряют блок сравнения данных
`dataStorageDiff` и приводят к падению тестов из-за непредсказуемого поведения.

Вы можете сказать фреймворку полностью игнорировать такие ключи с помощью параметра `ignore: true`:

```yaml
schemas:
  # Полностью игнорируем любые ключи блокировок Redisson Lock
  "redisson_lock:":
    ignore: true
```

Игнорируемые ключи будут автоматически отфильтрованы и не попадут в отчёты сравнения и блоки
`dataStorageDiff`.

Полный практический пример конфигурационного файла (application-test.yml)
-------------------------------------------------------------------------

Ниже представлен пример настройки тестовой среды с двумя Redis-подключениями и иерархическим
переопределением сериализации:

```yaml
integration:
  testing:
    redis:
      # --- УРОВЕНЬ 1: Глобальные настройки ---
      host: ${embedded.redis.host}
      port: ${embedded.redis.port}
      password: ${embedded.redis.password}
      syncBarrierTimeoutMs: 10000   # Ждём подтверждения транзакций до 10 секунд

      # Исключаем технические даты для всех DTO во всех базах по умолчанию
      excludedFields:
        - "createdAt"
        - "updatedAt"

      # По умолчанию все данные считаются обычными строками
      defaultSchema:
        class-ref: io.github.dimkich.integration.testing.redis.schema.StringRedisDataSchema

      connections:
        # --- УРОВЕНЬ 2: Подключение "redissonConnectionFactory" ---
        redissonConnectionFactory:
          defaultSchema:
            # Переопределяем схему на RedissonClient
            bean-ref: "redissonClient"
          schemas:
            # --- УРОВЕНЬ 3: Схемы этого подключения ---
            "[redisson.TestRedisDto]":
              bean-ref: "testRedisTemplate"
              excludedFields:
                - "metrics.hits"   # Дополнительно исключаем счётчик кликов внутри DTO
            "[redisson.bit]":
              class-ref: "io.github.dimkich.integration.testing.redis.schema.ByteArrayRedisDataSchema"
            "redisson_lock:":
              ignore: true

        # --- УРОВЕНЬ 2: Подключение "jedisConnectionFactory" ---
        jedisConnectionFactory:
          multipleDatabases: true
          defaultSchema:
            excludedFields:
              - "version"           # Дополнительно исключаем версию для этого подключения
          schemas:
            redisson:
              ignore: true
```
